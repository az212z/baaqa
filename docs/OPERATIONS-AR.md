# تشغيل باقة التجارية

## ما تم تسليمه

- نسخة عرض ثابتة متوافقة مع GitHub Pages.
- نسخة تجارية بحساب مالك وحساب لكل محل، قاعدة SQLite، كلمة مرور مشتقة بـ scrypt، جلسات HttpOnly، عزل البيانات، حدود كروت وصلاحية اشتراك.
- روابط كروت قصيرة قابلة للتعديل والتعطيل، توليد جماعي، اسم المحل، نسخ احتياطية للمكتبة وتصدير PNG/SVG وطباعة.
- النشر عبر Docker وCaddy مع HTTPS وتخزين دائم، واختبارات تنفيذية.

لا توجد بوابة تحصيل إلكتروني أو فواتير ضريبية أو رسائل آلية. البيع والتفعيل يدويان. لا توجد حسابات موظفين متعددة للمحل أو تحليلات مسح. هذه ليست ميزات مفعلة.

## متطلبات الإنتاج

خادم يدعم Docker Compose، نطاق فرعي موجّه إلى عنوان الخادم، ومنفذا 80 و443. لا تصلح GitHub Pages لتشغيل API وقاعدة بيانات. تثبيت واحد وقاعدة SQLite واحدة على قرص دائم؛ لا تشغل نسخًا متعددة على قاعدة ملف مشتركة.

1. انسخ المشروع إلى الخادم.
2. انسخ `.env.example` إلى `.env`، واستبدل DOMAIN بالنطاق الفعلي وADMIN_PASSWORD بكلمة عشوائية قوية. لا تستخدم قيمة المثال. لا ترفع الملف إلى GitHub.
3. نفّذ `docker compose up -d --build`.
4. افتح النطاق عبر HTTPS. يصدر Caddy الشهادة عندما يكون DNS والمنفذان مضبوطين.
5. ادخل باسم `admin` وكلمة المرور التي وضعتها. لا توجد كلمة مرور جاهزة أو مضمّنة في المشروع.
6. أضف محلًا باسم مستخدم لاتيني وكلمة مرور 12 حرفًا على الأقل، ونهاية اشتراك وحصة إجمالية.
7. سلّم بيانات الدخول عبر قناة خاصة. يغيّر المحل كلمة المرور من «هوية المحل».
8. أنشئ كرت اختبار على النطاق النهائي، امسحه بجوال، عدّله ثم اختبر نفس الباركود.

نشر الإنتاج على استضافة خارجية يحتاج توفير الخادم والنطاق؛ لا يحوّل نشر نسخة العرض على GitHub المنتج إلى SaaS مستضاف.

## التشغيل المحلي

Node.js 24 أو أحدث. نفّذ `npm ci` ثم `npm run build:commercial`.
اضبط متغير ADMIN_PASSWORD عبر مدير أسرار أو بيئة الطرفية، ثم `npm start`.
العنوان المحلي http://localhost:3000. استخدم NODE_ENV=production خلف HTTPS فقط لأن ملفات تعريف الجلسة تصبح Secure.

للتصميم ونسخة العرض: `npm run dev` على http://localhost:4173.

## إدارة الاشتراكات

الحصة إجمالية منذ إنشاء الحساب. عند التجديد زد الحصة الإجمالية وحدّث التاريخ. مثال: استخدم المحل 400 من 500 كرت، واشتريت له 500 أخرى، اجعل الحد 1000. لا يوجد خصم مالي تلقائي.

انتهاء الاشتراك أو إيقاف الدخول يمنع الإنشاء وإدارة الحساب. كروت العملاء السابقة تبقى متاحة. يوقف المحل كرتًا محددًا من المحفوظة ويستطيع إعادة تفعيله. تغيير كلمة المرور من لوحة المالك يُخرج جلسات ذلك المحل.

## البيانات والنسخ الاحتياطي

- قاعدة البيانات داخل volume اسمه baaqa_data. لا تنفّذ `docker compose down -v` على بيانات حقيقية.
- انسخ القاعدة بواجهة backup الخاصة بـ SQLite، لا تنسخ ملفًا نشطًا وحده وتتجاهل WAL.
- للاستخدام المباشر: `node scripts/backup.mjs /secure/path/baaqa-backup.sqlite` مع DATABASE_PATH الصحيح.
- للاستخدام عبر Docker: أوقف التطبيق مؤقتًا، انسخ مجلد `/app/data` كاملًا باستخدام `docker compose cp app:/app/data ./secure-backup`، ثم شغله. خزّن النسخة خارج الخادم بوصول مقيد. اختبر الاستعادة على بيئة منفصلة قبل الاعتماد عليها.
- النسخة JSON داخل واجهة المحل تحفظ بيانات كروته فقط. استيرادها ينشئ كروتًا جديدة ويستهلك الحصة، ولا يعيد معرفات وروابط القاعدة القديمة.
- لا تغيّر النطاق بعد توزيع QR إلا مع إبقاء النطاق القديم وإعادة توجيهه. الرابط القصير يعتمد على قاعدة البيانات والاستضافة.
- تدوير كلمة مرور المالك يتم بتغيير ADMIN_PASSWORD وإعادة تشغيل التطبيق. لتسجيل خروج جميع جلسات المالك أيضًا، احذف سجلات جلسات role=admin باستخدام إجراء صيانة محلي موثوق.

## التحديث

خذ نسخة احتياطية، ثم اسحب الإصدار المطلوب وأعد `docker compose up -d --build`. تحقق من الدخول وفتح كرت قديم. لا تلمس volume البيانات.
